# 后端接口约定

这份文档用于记录接口契约。目标是让前后端对数据结构、错误表达和分页行为有一致理解。

## 响应结构

建议接口返回稳定结构，避免同一个字段在不同状态下出现多种类型。

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

## 错误处理

错误信息应同时服务开发排查和用户提示。面向用户的文案要清楚，面向开发的排查信息可以放入日志或调试字段。

| 字段 | 含义 |
| --- | --- |
| `code` | 业务错误码 |
| `message` | 可读错误信息 |
| `data` | 成功时的数据 |

## 分页

分页接口应明确页码从 `1` 开始还是从 `0` 开始。建议统一为 `page` 从 `1` 开始，`pageSize` 表示每页数量。

```json
{
  "page": 1,
  "pageSize": 20,
  "total": 128,
  "items": []
}
```

## 命名

字段名应保持含义稳定。避免同一概念在不同接口中同时出现 `userId`、`uid`、`memberId` 等多种表达，除非它们确实代表不同业务对象。
