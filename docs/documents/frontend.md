# 前端开发规范

这份文档用于沉淀前端开发中的稳定约定。具体项目可以在此基础上补充框架、目录结构和组件库规则。

## 组件职责

组件应保持职责清楚，优先按照业务意图命名。一个组件只处理一个主要问题：展示、交互、数据协调或页面编排。

当组件变得难以阅读时，优先拆出明确的小组件或组合函数，而不是增加过深的配置对象。

## 状态管理

状态优先放在离使用位置最近的地方。只有当状态需要跨页面、跨模块共享，或需要持久化时，再提升到全局状态。

常见状态类型：

| 类型 | 放置位置 |
| --- | --- |
| 表单临时值 | 页面或表单组件内部 |
| 弹窗开关 | 触发弹窗的页面或局部组件 |
| 用户信息 | 全局状态或请求缓存 |
| 接口列表 | 请求缓存、页面状态或业务 store |

## 样式组织

样式命名应短、清楚、能表达结构含义。避免把颜色、尺寸或临时状态写进类名。

如果项目使用组件库，优先复用已有组件和设计变量。只有在组件库无法表达当前需求时，再添加局部样式。

## 列表渲染

列表渲染需要稳定的唯一标识时，优先使用业务 `id`。如果确实没有稳定标识，并且列表不会重排、插入或删除，可以使用 `index`。

## 提交前检查

- 页面状态是否覆盖空态、加载态、错误态。
- 文案是否能被真实用户理解。
- 样式是否在移动端和桌面端都能正常阅读。
- 新增逻辑是否可以被更简单的数据结构表达。
