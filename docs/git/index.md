## 建议工作流

日常开发可以按照这个顺序处理：

1. 拉取最新代码。
2. 新建或切换到功能分支。
3. 小步提交，提交信息写清楚完成了什么。
4. 推送分支并发起合并请求。
5. 合并前处理冲突、检查差异、确认没有提交无关文件。

Git 本身不复杂，真正容易出问题的是协作边界不清、提交太大、分支没有同步、误把本地配置或临时文件提交上去。把操作流程固定下来，很多问题会自然减少。
