<div>
<span>一些套路的解释&#xff0c;但是很有必要了解一下&#xff1a;</span>
</div>
<div>
<span>2.1&#xff1a;include_once语句&#xff1a;</span>
</div>
<div>
<span>它将安装到网站的smarty文件包含到当前文件中&#xff0c;注意包含的路径一定要写正确。</span>
</div>
<div>
<span>2.2&#xff1a;<code>$smarty</code> &#61; <code>new Smarty()</code>:</span>
</div>
<div>
<span>这一句新建一个Smarty对象<code>$smarty</code>,简单的一个对象的实例化。</span>
</div>
<div>
<span>2.3&#xff1a;<code>$smarty</code>-&gt;<code>templates(&#34;&#34;)</code>:</span>
</div>
<div>
<span>这一句指明<code>$smarty</code>对象使用tpl模板时的路径&#xff0c;它是一个目录&#xff0c;在没有这一句时&#xff0c;Smarty默认的模板路径为当前目录的</span>
<span>templates目录&#xff0c;实际在写程序时&#xff0c;我们要将这一句写明&#xff0c;这也是一种好的程序风格。</span>
</div>
<div>
<span>2.4&#xff1a;<code>$smarty</code>-&gt;<code>templates_c(&#34;&#34;)</code>:</span>
</div>
<div>
<span>这一句指明<code>$smarty</code>对象进行编译时的目录。在模板设计篇我们已经知道Smarty是一种编译型模板语言&#xff0c;而这个目录&#xff0c;就是</span>
<span>它编译模板的目录&#xff0c;要注意&#xff0c;如果站点位于</span>
<a target="_blank" href="http://lib.csdn.net/base/linux" rel="nofollow noopener noreferrer"><span><strong>Linux</strong></span></a>
<span>服务器上&#xff0c;请确保</span>
<span>teamplates_c里定义的这个目录具有可写可读权限&#xff0c;默认情况下它的编译目录是当前目录下的templates_c&#xff0c;出于同样的理</span>
<span>由我们将其明确的写出来。</span>
</div>
<div>
<span>2.5&#xff1a;<code>$smarty</code>-&gt;left_delimiter与<code>$smarty</code>-&gt;right_delimiter:</span>
</div>
<div>
<span>指明在查找模板变量时的左右分割符。默认情况下为&#34;{&#34;与&#34;}&#34;&#xff0c;但在实际中因为我们要在模板中使用<code>&lt;script&gt;</code>,Script中的函数</span>
<span>定义难免会</span>
</div>
<div>
<span>使用{}&#xff0c;虽然它有自己的解决办法&#xff0c;但习惯上我们将它重新定义为&#34;{#&#34;与&#34;#}&#34;或是&#34;&lt;!--{&#34;与&#34;}--&gt;&#34;或其它标志符&#xff0c;注</span>
<span>意&#xff0c;如果在这里定义了左右</span>
</div>
<div>
<span>分割符后&#xff0c;在模板文件中相应的要使每一个变量使用与定义相同的符号&#xff0c;例如在这里指定为&#34;</span>
<span>&lt;{&#34;与&#34;}&gt;&#34;&#xff0c;htm模板中也要相应的将{<code>$name</code>}变</span>
</div>
<div>
<span>成&lt;{<code>$name</code>}&gt;,这样程序才可以正确的找到模板变量。</span>
</div>
<div>
<span>2.6&#xff1a;<code>$smarty</code>-&gt;<code>cache(&#34;./cache&#34;)</code>:</span>
</div>
<div>
<span>告诉Smarty输出的模板文件缓存的位置。上一篇我们知道Smarty最大的优点在于它可以缓存&#xff0c;这里就是设置缓存的目录。</span>
<span>默认情况下</span>
</div>
<div>
<span>为当前目录下的cache目录&#xff0c;与templates_c目录相当&#xff0c;在</span>
<a target="_blank" href="http://lib.csdn.net/base/linux" rel="nofollow noopener noreferrer"><span><strong>linux</strong></span></a>
<span>系统中我们要确保它的可读可写性。</span>
</div>
<div>
<span>2.7&#xff1a;<code>$smarty</code>-&gt;cache_lifetime &#61; 60 * 60 * 24:</span>
</div>
<div>
<span>这里将以秒为单位进行计算缓存有效的时间。第一次缓存时间到期时当Smarty的caching变量设置为true时缓存将被重建。</span>
<span>当它的取值</span>
</div>
<div>
<span>为-1时表示建立起的缓存从不过期&#xff0c;为0时表示在程序每次执行时缓存总是被重新建立。上面的设置表示将</span>
<span>cache_lifetime设置为一天。</span>
</div>
<div>
<span>2.8&#xff1a;<code>$smarty</code>-&gt;caching &#61; 1:</span>
</div>
<div>
<span>这个属性告诉Smarty是否要进行缓存以及缓存的方式。它可以取3个值&#xff0c;0&#xff1a;Smarty默认值&#xff0c;表示不对模板进行缓存&#xff1b;1&#xff1a;</span>
<span>表示Smarty将</span>
</div>
<div>
<span>使用当前定义的cache_lifetime来决定是否结束cache&#xff1b;2&#xff1a;表示Smarty将使用在cache被建立时使用</span>
<span>cache_lifetime这个值。习惯上使用true与</span>
</div>
<div>
<span>false来表示是否进行缓存。</span>
</div>
<div>
<span>2.9&#xff1a;<code>$smarty</code>-&gt;<code>assign(&#34;name&#34;, &#34;zaocha&#34;)</code>&#xff1a;</span>
</div>
<div>
<span>该数的原型为<code>assign(string varname, mixed var)</code>,varname为模板中使用的模板变量&#xff0c;var指出要将模板变量替换的变量</span>
<span>名&#xff1b;其第二种原形为</span>
</div>
<div>
<span><code>assign(mixed var)</code>&#xff0c;我们要在后面的例子详细的讲解这个成员函数的使用方法&#xff0c;assign是Smarty的核心函</span>
<span>数之一&#xff0c;所有对模板变量的替</span>
</div>
<div>
<span>换都要使</span>
<span>用它。</span>
</div>
<div>
<span>2.10&#xff1a;<code>$smarty</code>-&gt;<code>display(&#34;index.tpl&#34;)</code>:</span>
</div>
<div>
<span>该函数原形为<code>display(string varname)</code>,作用为显示一个模板。简单的讲&#xff0c;它将分析处理过的模板显示出来&#xff0c;这里的模板文</span>
<span>件不用加路</span>
</div>
<div>
<span>径&#xff0c;只要使用一个文件名就可以了&#xff0c;它路径我们已经在<code>$smarty</code>-&gt;<code>templates(string path)</code>中定义过了。</span>
</div>
<div>
<span>程序执行完后我们可以打开当前目录下的templates_c与cache目录&#xff0c;就会发现在下边多出一些%%的目录&#xff0c;这些目录就是</span>
<span>Smarty的编译</span>
</div>
<div>
<span>与缓存目录&#xff0c;它由程序自动生成&#xff0c;不要直接对这些生成的文件进行修改。</span>
</div>
<div>
<span><strong>3、Smarty的注释&#xff1a;</strong></span>
</div>
<div>
<span>枯燥的文字部分可以忽略&#xff1a;</span>模板注释被*星号包围&#xff0c;而两边的星号又被定界符包围&#xff0c;例如 {* this is a comment *} 。smarty注释不会在模板文件的最后输出中出现&#xff0c;这与&lt;!-- HTML 注释--&gt;不同&#xff08;译注&#xff1a;html注释在页面源码中可见&#xff0c;而smarty注释则不能&#xff09;。这点非常有用&#xff0c;试想&#xff0c;注释只存在于模板里面&#xff0c;而在输出的页面中谁也看不见:)。
</div>
