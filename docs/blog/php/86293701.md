# phar的认识与使用

<p>对于Web应用的开发&#xff0c;如果你没用使用正确的工具&#xff0c;那开发过程可能会变得困难和痛苦。如果你之前开发过Java程序&#xff0c;我相信你肯定知道Jar文件(Jar是Java ARchive的缩写)。一个应用&#xff0c;包括所有的可执行、可访问的文件&#xff0c;都打包进了一个JAR文件里&#xff0c;使得部署过程十分简单。</p>
<p>PHAR (“Php ARchive”) 是PHP里类似于JAR的一种打包文件。如果你使用的是 PHP 5.3 或更高版本&#xff0c;那么Phar后缀文件是默认开启支持的&#xff0c;你不需要任何其他的安装就可以使用它。</p>
<p>如果你以前没有使用过Phar文件&#xff0c;这篇文件就是要介绍关于这种文件的一些重要特征。希望你能发现Phar是一个非常有用的技术&#xff0c;能给你的PHP开发和部署带来更快更好的体验。</p>
<p>PHAR文件缺省状态是只读的&#xff0c;使用Phar文件不需要任何的配置。部署非常方便。因为我们现在需要创建一个自己的Phar文件&#xff0c;所以需要允许写入Phar文件&#xff0c;这需要修改一下 <code>php.ini</code></p>
<p>打开 <code>php.ini</code>&#xff0c;找到 <code>phar.readonly</code> 指令行&#xff0c;修改成:</p>
<div class="language-ini vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">ini</span><pre class="vp-code" tabindex="0" v-pre><code>phar.readonly = 0</code></pre></div>
<p>现在&#xff0c;我们就可以来把PHP应用打包成Phar文件了。</p>
<h3><a></a>我们的第一个 PHAR 文件</h3>
<p>首先我要按按照一个的规则创建应用的目录结构&#xff0c;就行下面这样&#xff1a;<br />
<img src="/images/blog/86293701/local-002.jpg" alt="在这里插入图片描述" /><br />
其中的 <code>build</code> 目录里将放置 PHAR 文件&#xff0c;这样能避免它跟源码程序混合到一起。<code>src</code> 放的就是我们的PHP源码。</p>
<p><code>index.php</code> 会成为我们的应用的入口程序&#xff0c;<code>common.php</code> 可以放置应用需要的一些共有代码&#xff0c;<code>config.ini</code> 是我们的配置文件。</p>
<p><code>index.php</code> 大概是这样样子&#xff1a;</p>
<div class="language-php vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">php</span><pre class="vp-code" tabindex="0" v-pre><code>&lt;?php
require_once "phar://myapp.phar/common.php";
$config = parse_ini_file("config.ini");
AppManager::run($config);</code></pre></div>
<p><code>common.php</code> 大概是这样的&#xff1a;</p>
<div class="language-php vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">php</span><pre class="vp-code" tabindex="0" v-pre><code>&lt;?php
class AppManager
{
  public static function run($config)
  {
    echo "Application is now running with the following configuration... ";
    var_dump($config);
  }
}</code></pre></div>
<p>而 <code>config.ini</code> 的内容是这样的&#xff1a;</p>
<div class="language-ini vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">ini</span><pre class="vp-code" tabindex="0" v-pre><code>[database]
host=localhost
db=dbname
user=myuser
pass=dbpass</code></pre></div>
<h3><a></a>创建 PHAR 文件</h3>
<p>在我们的PHP应用目录里&#xff0c;需要有一个创建Phar文件的脚本&#xff0c;我们给它起名叫 <code>create-phar.php</code>&#xff0c;放置到 <code>myapp</code> 的跟目录下&#xff0c;里面添加如下代码&#xff1a;</p>
<div class="language-php vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">php</span><pre class="vp-code" tabindex="0" v-pre><code>&lt;?php
$srcRoot = "~/myapp/src";
$buildRoot = "~/myapp/build";
$phar = new Phar($buildRoot . "/myapp.phar", FilesystemIterator::CURRENT_AS_FILEINFO |       FilesystemIterator::KEY_AS_FILENAME, "myapp.phar");
$phar["index.php"] = file_get_contents($srcRoot . "/index.php");
$phar["common.php"] = file_get_contents($srcRoot . "/common.php");
$phar-&gt;setStub($phar-&gt;createDefaultStub("index.php"));
copy($srcRoot . "/config.ini", $buildRoot . "/config.ini");</code></pre></div>
<p>打开命令行窗口&#xff0c;切换到 myapp 目录下&#xff0c;运行命令&#xff1a;</p>
<div class="language-shell vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">shell</span><pre class="vp-code" tabindex="0" v-pre><code>aabouzekry@platinum:~/myapp$ php create-phar.php</code></pre></div>
<p>运行了上面的命令后&#xff0c;你会在 <code>build</code> 目录里发现一个 <code>myapp.phar</code> 文件&#xff0c;还有一个<code>config.ini</code>的副本。将这两个文件拷贝到WEB服务器的服务根目录里(e.g. htdocs)。</p>
<p>我们可以直接访问Phar打包的应用&#xff0c;但这需要额外配置web server来将Phar文件发送给正确PHP解析器。另外一个办法是创建一个run脚本&#xff0c;include 这个Phar文件。</p>
<p>在web server的根目录创建一个叫 <code>run.php</code> 的PHP脚本&#xff1a;</p>
<div class="language-php vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">php</span><pre class="vp-code" tabindex="0" v-pre><code>&lt;?php
require "myapp.phar";</code></pre></div>
<p>这段代码的作用就是可以让你免去了去配置web server来直接解析Phar文件。如果你的应用使用的是一个共享的虚拟主机&#xff0c;没有权限来配置web server&#xff0c;那么&#xff0c;这种方式是一个完美的解决方案。</p>
<p>创建了<code>run.php</code>后&#xff0c;我们的web server的根目录会变成这样&#xff1a;<br />
<img src="/images/blog/86293701/local-003.jpg" alt="在这里插入图片描述" /><br />

<h3><a></a>Phar的运行原理</h3>
<p>让我们再重新看一下 <code>create-phar.php</code> 中的代码&#xff0c;了解每段代码的作用。先看看这几行&#xff1a;</p>
<div class="language-php vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">php</span><pre class="vp-code" tabindex="0" v-pre><code>&lt;?php
$phar = new Phar($buildRoot . "/myapp.phar", FilesystemIterator::CURRENT_AS_FILEINFO |
FilesystemIterator::KEY_AS_FILENAME, "myapp.phar");</code></pre></div>
<p>一个新 <code>Phar</code> 对象的创建通常需要三个参数。第一个参数是<code>Phar</code>文件的路径。你不仅可以通过它创建<code>Phar</code>文件&#xff0c;还可以对现存的<code>Phar</code>文件进行操作。</p>
<p>第二个参数是设定 Phar 对象如何处理文件。Phar 对象继承了 PHP <code>RecursiveDirectoryIterator</code> 对象&#xff0c;这个参数是直接传递到父类里。这里提供的值是<code>RecursiveDirectoryIterator</code> 的缺省值&#xff0c;能满足目前的要求。</p>
<p>第三个参数是<code>Phar</code>文件的别名&#xff0c;在内部引用这个<code>Phar</code>文件时都要使用这个别名。也就是说&#xff0c;<code>Phar</code>内部文件的相互<code>include</code>都需要显式的使用这个别名。例如&#xff0c;之前的<code>index.php</code> 对 <code>common.php</code> 的引用就是这种方式。</p>
<div class="language-php vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">php</span><pre class="vp-code" tabindex="0" v-pre><code>&lt;?php
require_once "phar://myapp.phar/common.php";</code></pre></div>
<p>在<code>Phar</code>对象创建之后&#xff0c; <code>index.php</code> 和 <code>common.php</code> 就被加入了<code>Phar</code>文件里了。<code>Phar</code> 对象是一个数组&#xff0c;<code>file_get_contents()</code> 方法将各个文件的内容读到数组里。你可以向里面添加很多的文件&#xff0c;但如果你考虑添加大量的文件&#xff0c;比如说整个目录下的文件&#xff0c;你可以考虑使用更方便的 <code>buildFromDirectory()</code> 方法。</p>
<div class="language-php vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">php</span><pre class="vp-code" tabindex="0" v-pre><code>&lt;?php
$phar-&gt;buildFromDirectory("/path/to/dir", '/.php$/');</code></pre></div>
<p><code>buildFromDirectory()</code> 的第一个参数是目录的路径&#xff1b;第二个参数是可选的&#xff0c;是用正则表达式过滤文件的类型。如果目录下的所有文件都要include&#xff0c;这个参数可以忽略。</p>
<p><code>setStub()</code> 用来创建stub文件&#xff0c;stub文件用来告诉Phar在被加载时干什么。<br />
最后&#xff0c;<code>config.ini</code> 从src被拷贝到build目录下。</p>
<h3><a></a>Stub文件</h3>
<p>运行Phar文件时&#xff0c;stub文件被当做一个meta文件来初始化Phar&#xff0c; 并告诉Phar文件在被调用时该做什么。在我们的例子中&#xff0c;使用的是 <code>createDefaultStub()</code> 方法&#xff0c;生成的缺省stub文件包含如下的代码&#xff1a;</p>
<div class="language-php vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">php</span><pre class="vp-code" tabindex="0" v-pre><code>&lt;?php
Phar::mapPhar();
include "phar://myapp.phar/index.php";
__HALT_COMPILER();</code></pre></div>
<p><code>createDefaultStub()</code> 方法缺省创建的stub文件的内容很简单。 <code>Phar::mapPhar()</code> 用来分析Phar文件的元数据&#xff0c;并初始化它。stub文件的结尾处需要调用 <code>__HALT_COMPILER()</code> 方法&#xff0c;这个方法后不能留空格。<code>__HALT_COMPILER()</code> 会立即终止PHP的运行&#xff0c;防止include的文件在此方法后仍然执行。这是Phar必须的&#xff0c;没有它Phar将不能正常运行。</p>
<p>除此之外&#xff0c;我们还可以创建自己的stub文件来执行自定义的初始化过程&#xff0c;像这样加载自定义文件&#xff1a;</p>
<div class="language-php vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">php</span><pre class="vp-code" tabindex="0" v-pre><code>&lt;?php
$phar-&gt;setStub(file_get_contents("stub.php"));</code></pre></div>
<h3><a></a>Phar文件的一些缺陷</h3>
<p>如果你开发的类库或可引用程序需要被多个项目使用&#xff0c;把它打包成Phar文件是一个省事的解决方案。Phar文件是经过高度优化过的&#xff0c;它和普通文件的执行效率相比完全不弱&#xff0c;所以&#xff0c;你不需要担心效率问题。</p>
<p>但需要注意的是&#xff0c;Phar文件的使用有一些限制。下面是一些提示让你更好的理解它&#xff1a;</p>
<ul>
<li>我们可以整个应用都打包到一个Phar文件里&#xff0c;但Phar只提供了一个单一入口。</li>
<li>在生产环境里&#xff0c;我们应该避免将东西回写进Phar&#xff0c;我们应该将哪些可能被修改的文件放到Phar之外&#xff0c;在标准PHP安装里&#xff0c;Phar是不允许回写的&#xff0c;因为安全问题。</li>
</ul>
<h3><a></a>总结</h3>
<p>Phar能帮我们在打包和部署PHP应用上免去大量的麻烦&#xff0c;我推荐大家试试它。这篇文章只是介绍了Phar的一些主要概念&#xff0c;包括如何创建Phar&#xff0c;include文件&#xff0c;介绍stub文件的作用&#xff0c;如何访问Phar里的文件。</p>
