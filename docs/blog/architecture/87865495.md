# 高性能消息中间件——NATS

<h2>1、介绍&#xff1a;</h2>
<p>NATS是<span>一个开源、轻量级、高性能的分布式消息中间件</span>&#xff0c;实现了高可伸缩性和优雅的<code>Publish/Subscribe</code>模型&#xff0c;使用Golang语言开发。NATS的开发哲学认为高质量的QoS应该在客户端构建。<strong>故只建立了Request-Reply&#xff0c;不提供 1.持久化 2.事务处理 3.增强的交付模式 4.企业级队列。</strong></p>
<h2>2、NATS消息传递模型</h2>
<p>NATS支持各种消息传递模型&#xff0c;包括&#xff1a;</p>
<ul>
<li><strong>发布订阅</strong>&#xff08;Publish Subscribe&#xff09;</li>
<li><strong>请求回复</strong>&#xff08;Request Reply&#xff09;</li>
<li><strong>队列订阅</strong>&#xff08;Queue Subscribers )</li>
</ul>
<h4>2.1、发布订阅&#xff08;Publish Subscribe&#xff09;</h4>
<p>NATS将<code>publish/subscribe</code>消息分发模型实现为一对多通信&#xff0c;发布者在Subject上发送消息&#xff0c;并且监听该Subject在任何活动的订阅者都会收到该消息</p>
<h4>2.2、请求响应&#xff08;Request Reply&#xff09;</h4>
<p>NATS支持两种请求响应消息&#xff1a;点对点或多对多。点对点涉及最快或首先响应。在一对多的消息交换中&#xff0c;需要限制请求响应的限制。</p>
<p>在Request Reply过程中&#xff0c;发布请求发布带有响应主题的消息&#xff0c;期望对该subject做出响应操作</p>
<p><strong>队列订阅&amp;分享工作&#xff08;Queue Subscribers &amp; Sharing Work&#xff09;</strong><br /> NATS提供称为队列订阅的负载均衡功能&#xff0c;虽然名字为<code>queue(队列)</code>但是并不是我们所认为的那样。他的主要功能是将具有相同queue名字的subject进行负载均衡。使用队列订阅功能消息发布者不需要做任何改动&#xff0c;消息接受者需要具有相同的对列名</p>
<h2>3、NATS提供的功能</h2>
<ul>
<li><strong>纯粹的发布订阅模型</strong>&#xff08;Pure pub-sub&#xff09;</li>
<li><strong>服务器集群</strong>&#xff08;Cluster mode server&#xff09;</li>
<li><strong>自动精简订阅者</strong>&#xff08;Auto-pruning of subscribers)</li>
<li><strong>基于文本协议</strong>&#xff08;Text-based protocol&#xff09;</li>
<li><strong>多服务质量保证</strong>&#xff08;Multiple qualities of service - QoS&#xff09;</li>
<li><strong>发布订阅</strong>&#xff08;Publish Subscribe&#xff09;</li>
</ul>
<h2>4、NATS Streaming介绍</h2>
<ul>
<li><strong>增强消息协议</strong>(Enhanced message protocol)</li>
<li><strong>消息/事件持久化</strong>(<code>Message/event</code> persistence)</li>
<li><strong>至少一次数据传输</strong>(At-least-once-delivery)</li>
<li><strong>Publisher限速(</strong>Publisher rate limiting)</li>
<li><strong>Subscriber速率匹配</strong>(Rate <code>matching/limiting</code> per subscriber)</li>
<li><strong>按主题重发消息</strong>(Historical message replay by subject)</li>
<li><strong>持续订阅</strong>(Durable subscriptions)</li>
</ul>
<h2>5、NATS与NATS Streaming</h2>
<ul>
<li><strong>弄清楚NATS与NATS Streaming各自的职责&#xff0c;区别和他们之间的交互至关重要</strong>&#xff1b;简单来说&#xff0c;NATS实现了基本的发布/订阅模型&#xff0c;NATS Streaming提供的则是更高级的特性&#xff0c;包括ACK,持久化等&#xff1b;</li>
<li><strong>理解NATS和NATS Streaming的区别最重要的是&#xff0c;NATS Streaming并不是在NATS上功能的增强&#xff0c;它与NATS之间仍然通过Client进行交互&#xff0c;他们的部署是独立的&#xff0c;NATS Streaming以类似于sidecar的形式服务于NATS</strong></li>
</ul>
<h3>5.1、NATS重点关注</h3>
<p><strong>     认证授权 &#xff1a;</strong></p>
<ul>
<li>NATS提供基于Token和用户名/密码的两种客户端认证方式&#xff1b; </li>
<li>提供基本的针对主题订阅和发布的权限管理&#xff1b;</li>
</ul>
<p><strong>     高可用集群</strong>&#xff1a;NATS部署高可用集群非常的简单&#xff0c;只需要在各个实例的配置文件中添加如下配置即可&#xff1b;其中集群可单独设置认证方式&#xff1b;</p>
<div class="language-text vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">text</span><pre class="vp-code" tabindex="0" v-pre><code>cluster {
host: '0.0.0.0'
port: 7248
routes = [ nats-route://192.168.59.103:7244
nats-route://192.168.59.103:7246]
}</code></pre></div>
<p><strong>     自动断开不健康的客户端连接</strong>&#xff1a;</p>
<p>         NATS Server和Client之间会维持PING-PONG检查&#xff0c;发现已断开或不健康的连接会主动断开&#xff1b;</p>
<blockquote>
<p>这是一种保证Server长时间高效运行的策略&#xff1b;</p>
</blockquote>
<p>
<strong>相对简单的监控界面</strong></p>
<p>通过以下启动参数可以提供一个简单的web监控界面&#xff0c;但是功能很简陋&#xff0c;需要进一步改善&#xff1b;为了弥补不足&#xff0c;提供nats-top工具查看更详尽的服务器信息&#xff1b;</p>
<div class="language-text vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">text</span><pre class="vp-code" tabindex="0" v-pre><code>-m your_port</code></pre></div>
<p><strong>     单个推送消息大小限制</strong></p>
<p>NATS单个消息的大小限制为1M&#xff0c;基本上是可以满足一般的数据传输的&#xff1b;</p>
<h3>5.2、NATS Streaming</h3>
<h4>5.2.1、介绍</h4>
<p><img alt="" height="309" src="/images/blog/87865495/local-001.png" width="469" /></p>
<p>了解NATS Streaming主要关注它为NATS Server提供新特性&#xff1b;主要关注的有以下几点&#xff1a;</p>
<p><strong>1).At-least-once-delivery &amp; Durable subscriptions</strong></p>
<p>至少一次投递和持久化&#xff0c;对于在分布式场景下保证数据的一致性非常有用&#xff1b;</p>
<p><strong>2).Historical message replay by subject &amp; 全局客户端ID唯一</strong></p>
<p>可以选择任意历史节点开始订阅恢复订阅</p>
<p><strong>3).多样化持久化支持</strong></p>
<p>默认将消息保存在内存中&#xff0c;同时支持file,mysql两种持久化支持&#xff1b;</p>
<h4>5.2.2、场景分析</h4>
<p><strong>场景一 高效传输&#xff08;不保证一致性&#xff09;</strong><br /> 其实在我们使用NATS的初期就是使用的这种模式&#xff0c;主要用于在各个模块信息同步&#xff08;比如&#xff0c;个人信息的同步&#xff09;&#xff0c;在时效性上和一致性上要求不高&#xff1b;这种场景只需要创建NATS Cluster即可&#xff1b;</p>
<p><strong>场景二 保证最终一致性</strong><br /> 一致性的保证主要是通过NATS Streaming提供的特性来完成&#xff0c;在微服务架构中,跨服务的调用链经常存在&#xff0c;如何保证在下游服务不可用或失败的情况下业务数据的一致性要求&#xff0c;NATS Streaming 提供的ACK机制和至少一次传递的特性就非常重要&#xff1b;甚至是要避免在NATS集群宕机恢复过程中可能的数据不一致情况的发生&#xff1b;举例的话&#xff0c;典型的场景包括支付和关键业务状态的更新&#xff1b;</p>
<h4>5.2.3、实践方案介绍</h4>
<p><strong>场景一</strong></p>
<p>在这种场景下&#xff0c;NATS的角色更多是高效传输层&#xff08;transport&#xff09;,完成数据的异步传输&#xff1b;因此&#xff0c;只需要部署NATS集群即可&#xff0c;并不需要Streaming提供的高级特性&#xff1b;套用以下模板&#xff0c;创建多节点的NATS集群即可&#xff1b;</p>
<p>集群部署<code>demo(以一个节点配置为例)</code></p>
