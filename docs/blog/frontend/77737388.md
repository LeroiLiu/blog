# 理解javascript中的with关键字

<p><span>这篇文章主要帮助大家理解 javascript 中的 with 关键字，学习 with 关键字的作用和常见注意点。</span></p>
<p> 说起js中的with关键字&#xff0c;很多小伙伴们的第一印象可能就是with关键字的作用在于改变作用域&#xff0c;然后最关键的一点是不推荐使用with关键字。听到不推荐with关键字后&#xff0c;我们很多人都会忽略掉with关键字&#xff0c;认为不要去管它用它就可以了。但是有时候&#xff0c;我们在看一些代码或者面试题的时候&#xff0c;其中会有with关键字的相关问题&#xff0c;很多坑是你没接触过的&#xff0c;所以还是有必要说说with这一个关键字。</p>
<p>
<strong>一、基本说明</strong></p>
<p> 在js高级程序设计中是这样描述with关键字的&#xff1a;with语句的作用是将代码的作用域设置到一个特定的作用域中&#xff0c;基本语法如下&#xff1a;</p>
<div>
<div>
<div>
<div class="language-javascript vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">javascript</span><pre class="vp-code" tabindex="0" v-pre><code>with (expression) statement;</code></pre></div>
</div>
</div>
</div>
<p> 使用with关键字的目的是为了简化多次编写访问同一对象的工作&#xff0c;比如下面的例子&#xff1a;<br />
</p>
<div>
<div>
<div>
<div class="language-javascript vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">javascript</span><pre class="vp-code" tabindex="0" v-pre><code>var qs = location.search.substring(1);
var hostName = location.hostname;
var url = location.href;</code></pre></div>
</div>
</div>
</div>
<p> 这几行代码都是访问location对象中的属性&#xff0c;如果使用with关键字的话&#xff0c;可以简化代码如下&#xff1a;<br />
</p>
<div>
<div>
<div>
<div class="language-javascript vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">javascript</span><pre class="vp-code" tabindex="0" v-pre><code>with (location) {
  var qs = search.substring(1);
  var hostName = hostname;
  var url = href;
}</code></pre></div>
</div>
</div>
</div>
<p> 在这段代码中&#xff0c;使用了with语句关联了location对象&#xff0c;这就以为着在with代码块内部&#xff0c;每个变量首先被认为是一个局部变量&#xff0c;如果局部变量与location对象的某个属性同名&#xff0c;则这个局部变量会指向location对象属性。<br /> 注意&#xff1a;在严格模式下不能使用with语句。</p>
<p>
<strong>二、with关键字的弊端</strong></p>
<p> 前面的基本说明中&#xff0c;我们可以看到with的作用之一是简化代码。但是为什么不推荐使用呢&#xff1f;下面我们来说说with的缺点&#xff1a;<br />
</p>
<p> 1、性能问题<br /> 2、语义不明&#xff0c;调试困难</p>
<p>
<strong>三、性能问题</strong></p>
<p> 首先说说性能问题&#xff0c;关于使用with关键字的性能问题&#xff0c;首先我们来看看两段代码&#xff1a;</p>
<p> 第一段代码是没有使用with关键字&#xff1a;<br />
</p>
<div>
<div>
<div>
<div class="language-javascript vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">javascript</span><pre class="vp-code" tabindex="0" v-pre><code>function func() {
  console.time("func");
  var obj = {
    a: [1, 2, 3]
  };
  for (var i = 0; i &lt; 1e5; i++) {
    var v = obj.a[0];
  }
  console.timeEnd("func");
}
func();</code></pre></div>
</div>
</div>
</div>
<p> 第二段代码使用了with关键字&#xff1a;<br />
</p>
<div>
<div>
<div>
<div class="language-javascript vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">javascript</span><pre class="vp-code" tabindex="0" v-pre><code>function funcWith() {
  console.time( "funcWith");
  var obj = {
    a: [1, 2, 3]
  }
  ;
  var obj2 = {
    x: 2
  }
  ;
  with (obj2) {
    console.log(x);
    for ( var i = 0; i &lt; 100000; i++) {
      var v = obj.a[0];
    }
  }
  console.timeEnd( "funcWith");
  //84.808ms
}
funcWith();</code></pre></div>
</div>
</div>
</div>
<p> 在使用了with关键字后了&#xff0c;代码的性能大幅度降低。第二段代码的with语句作用到了obj2这个对象上&#xff0c;然后with块里面访问的却是obj对象。有一种观点是&#xff1a;使用了with关键字后&#xff0c;在with块内访问变量时&#xff0c;首先会在obj2上查找是否有名为obj的属性&#xff0c;如果没有&#xff0c;再进行下一步查找&#xff0c;这个过程导致了性能的降低。但是程序性能真正降低的原因真的是这样吗&#xff1f;<br /> 我们修改一下第二段代码&#xff0c;修改如下&#xff1a;<br />
</p>
<div>
<div>
<div>
<div class="language-javascript vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">javascript</span><pre class="vp-code" tabindex="0" v-pre><code>function funcWith() {
  console.time( "funcWith");
  var obj = {
    a: [1, 2, 3]
  }
  ;
  with (obj) {
    for ( var i = 0; i &lt; 100000; i++) {
      var v = a[0];
    }
  }
  console.timeEnd( "funcWith");
  //88.260ms
}
funcWith();</code></pre></div>
</div>
</div>
</div>
<p> 这段代码将with语句作用到了obj对象上&#xff0c;然后直接使用a访问obj的a属性&#xff0c;按照前面说到的观点&#xff0c;访问a属性时&#xff0c;是一次性就可以在obj上找到该属性的&#xff0c;但是为什么代码性能依旧降低了呢。<br /> 真正的原因是&#xff1a;使用了with关键字后&#xff0c;JS引擎无法对这段代码进行优化。<br /> JS引擎在代码执行之前有一个编译阶段&#xff0c;在不使用with关键字的时候&#xff0c;js引擎知道a是obj上的一个属性&#xff0c;它就可以静态分析代码来增强标识符的解析&#xff0c;从而优化了代码&#xff0c;因此代码执行的效率就提高了。使用了with关键字后&#xff0c;js引擎无法分辨出a变量是局部变量还是obj的一个属性&#xff0c;因此&#xff0c;js引擎在遇到with关键字后&#xff0c;它就会对这段代码放弃优化&#xff0c;所以执行效率就降低了。<br /> 使用with关键字对性能的影响还有一点就是js压缩工具&#xff0c;它无法对这段代码进行压缩&#xff0c;这也是影响性能的一个因素。</p>
<p>
<strong>四、语义不明&#xff0c;难以调试</strong></p>
<p> 前面说到除了性能的问题&#xff0c;with还存在的一个缺点语义不明&#xff0c;难以调试&#xff0c;就是造成代码的不易阅读&#xff0c;而且可能造成潜在的bug。<br />
</p>
<div>
<div>
<div>
<div class="language-javascript vp-adaptive-theme"><button title="Copy Code" class="copy"></button><span class="lang">javascript</span><pre class="vp-code" tabindex="0" v-pre><code>function foo(obj) {
  with (obj) {
    a = 2;
  }
}
var o1 = {
  a: 3
}
;
var o2 = {
  b: 3
}
;
foo(o1);
console.log(o1.a);
// 2
foo(o2);
console.log( o2.a );
// undefined
console.log( a );
// 2</code></pre></div>
</div>
</div>
</div>
<p> 这段代码很容易理解了&#xff0c;在foo函数内&#xff0c;使用了with关键字来访问传进来的obj对象&#xff0c;然后修改a属性。当传入o1对象时&#xff0c;因为o1对象存在着a属性&#xff0c;所以这样没有问题。传入o2对象时&#xff0c;在修改a属性时&#xff0c;由于o2对象没有a这个属性&#xff0c;所以被修改的a属性则变成了全局变量。这就造成了潜在的bug。</p>
<p>
<strong>五、延伸分析</strong></p>
<p> 前面说了那么多&#xff0c;相信大家已经理解了为什么不推荐使用with关键字以及可能存在的问题。下面我们来看看一些更复杂的情况&#xff0c;看下面的代码&#xff1a;<br />
</p>

<span><strong>1、this关键字</strong></span><br /> 关于this关键字的文章google上面相当多&#xff0c;这里不再赘述&#xff0c;我们只需记住一点&#xff1a;this关键字始终指向调用函数的对象。在这里&#xff0c;foo函数中&#xff0c;this指向的就是obj对象。因此在<code>with(this)</code>语句块里面&#xff0c;可以直接通过x变量来访问obj的x属性。<br />
<span><strong>2、变量提升</strong></span><br /> js中的变量提升也是一个经常遇到的问题&#xff0c;我们可以简单理解成在js中&#xff0c;变量声明会被提升到函数的顶部&#xff0c;尽管有的时候&#xff0c;它是在后面声明的。</p>
