<h2>八、<strong>Memcache的使用</strong></h2>
<div>
<span>使用Memcache的网站一般流量都是比较大的&#xff0c;为了缓解数据库的压力&#xff0c;让Memcache作为一个缓存区域&#xff0c;把部分信息保存在内存中&#xff0c;在前端能够迅速的进行存取。那么一般的焦点就是集中在如何分担数据库压力和进行分布式&#xff0c;毕竟单台Memcache的内存容量的有限的。这里简单整理一些个人看法。</span>
</div>
<div>
<span><em>分布式应用</em></span>
</div>
<div>
<span>Memcache本来支持分布式&#xff0c;我们客户端稍加改造&#xff0c;更好的支持。我们的key可以适当进行有规律的封装&#xff0c;比如以user为主的网站来说&#xff0c;每个用户都有User ID&#xff0c;那么可以按照固定的ID来进行提取和存取&#xff0c;比如1开头的用户保存在第一台Memcache服务器上&#xff0c;以2开头的用户的数据保存在第二胎Mecache服务器上&#xff0c;存取数据都先按照User ID来进行相应的转换和存取。</span>
</div>
<div>
<span>但是这个有缺点&#xff0c;就是需要对User ID进行判断&#xff0c;如果业务不一致&#xff0c;或者其他类型的应用&#xff0c;可能不是那么合适&#xff0c;那么可以根据自己的实际业务来进行考虑&#xff0c;或者去想更合适的方法。</span>
</div>
<div>
<span><em>减少数据库压力</em></span>
</div>
<div>
<span>这个算是比较重要的&#xff0c;所有的数据基本上都是保存在数据库当中的&#xff0c;每次频繁的存取数据库&#xff0c;导致数据库性能极具下降&#xff0c;无法同时服务更多的用户&#xff0c;比如MySQL&#xff0c;特别频繁的锁表&#xff0c;那么让Memcache来分担数据库的压力吧。我们需要一种改动比较小&#xff0c;并且能够不会大规模改变前端的方式来进行改变目前的架构。</span>
</div>
<div>
<span>我考虑的一种简单方法&#xff1a;</span>
</div>
<div>
<span>后端的数据库操作模块&#xff0c;把所有的 Select 操作提取出来&#xff08;<code>update/delete/insert</code> 不管&#xff09;&#xff0c;然后把对应的 SQL 进行相应的 hash 算法计算得出一个 hash 数据 key&#xff08;比如 MD5 或者 SHA&#xff09;&#xff0c;然后把这个 key 去 Memcache 中查找数据&#xff0c;如果这个数据不存在&#xff0c;说明还没写入到缓存中&#xff0c;那么从数据库把数据提取出来&#xff0c;一个是数组类格式&#xff0c;然后把数据再 set 到 Memcache 中&#xff0c;key 就是这个 SQL 的 hash 值&#xff0c;然后相应的设置一个失效时间&#xff0c;比如一个小时&#xff0c;那么一个小时中的数据都是从缓存中提取的&#xff0c;有效减少数据库的压力。缺点是数据不实时&#xff0c;当数据做了修改以后&#xff0c;无法实时到前端显示&#xff0c;并且还有可能对内存占用比较大&#xff0c;毕竟每次 select 出来的数据数量可能比较巨大&#xff0c;这个是需要考虑的因素。</span>
</div>
<h2><strong>九、Memcache的安全</strong></h2>
<div>
<span>我们上面的Memcache服务器端都是直接通过客户端连接后直接操作&#xff0c;没有任何的验证过程&#xff0c;这样如果服务器是直接暴露在互联网上的话是比较危险&#xff0c;轻则数据泄露被其他无关人员查看&#xff0c;重则服务器被入侵&#xff0c;因为Mecache是以root权限运行的&#xff0c;况且里面可能存在一些我们未知的bug或者是缓冲区溢出的情况&#xff0c;这些都是我们未知的&#xff0c;所以危险性是可以预见的。为了安全起见&#xff0c;我做两点建议&#xff0c;能够稍微的防止黑客的入侵或者数据的泄露。</span>
</div>
<div>
<span><em>内网访问</em></span>
</div>
<div>
<span>最好把两台服务器之间的访问是内网形态的&#xff0c;一般是Web服务器跟Memcache服务器之间。普遍的服务器都是有两块网卡&#xff0c;一块指向互联网&#xff0c;一块指向内网&#xff0c;那么就让Web服务器通过内网的网卡来访问Memcache服务器&#xff0c;我们Memcache的服务器上启动的时候就监听内网的IP地址和端口&#xff0c;内网间的访问能够有效阻止其他非法的访问。</span>
</div>
<div>
<span># memcached <code>-d</code> <code>-m</code> 1024 <code>-u</code> root <code>-l</code> 192.168.0.200 <code>-p</code> 11211 <code>-c</code> 1024 <code>-P</code> <code>/tmp/memcached.pid</code></span>
</div>
<div>
<span>Memcache服务器端设置监听通过内网的192.168.0.200的ip的11211端口&#xff0c;占用1024MB内存&#xff0c;并且允许最大1024个并发连接</span>
</div>
<div>
<span><em>设置防火墙</em></span>
</div>
<div>
<span>防火墙是简单有效的方式&#xff0c;如果却是两台服务器都是挂在网的&#xff0c;并且需要通过外网IP来访问Memcache的话&#xff0c;那么可以考虑使用防火墙或者代理程序来过滤非法访问。</span>
</div>
<div>
<span>一般我们在Linux下可以使用iptables或者FreeBSD下的ipfw来指定一些规则防止一些非法的访问&#xff0c;比如我们可以设置只允许我们的Web服务器来访问我们Memcache服务器&#xff0c;同时阻止其他的访问。</span>
</div>
<div>
<span># iptables -F</span>
</div>
<div>
<span># iptables <code>-P</code> INPUT DROP</span>
</div>
<div>
<span># iptables <code>-A</code> INPUT <code>-p</code> tcp <code>-s</code> 192.168.0.2 <code>--dport</code> 11211 <code>-j</code> ACCEPT</span>
</div>
<div>
<span># iptables <code>-A</code> INPUT <code>-p</code> udp <code>-s</code> 192.168.0.2 <code>--dport</code> 11211 <code>-j</code> ACCEPT</span>
</div>
<div>
<span>上面的iptables规则就是只允许192.168.0.2这台Web服务器对Memcache服务器的访问&#xff0c;能够有效的阻止一些非法访问&#xff0c;相应的也可以增加一些其他的规则来加强安全性&#xff0c;这个可以根据自己的需要来做。</span>
</div>
</div>
