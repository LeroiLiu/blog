这个站点的价值来自持续整理。新增内容时，优先判断它属于正式文档还是常见问题。

## 什么时候写文档

适合写成文档的内容：

- 长期有效的规范。
- 多人协作需要遵守的流程。
- 项目架构、接口约定和部署说明。
- 需要背景解释的实践经验。

## 什么时候写 FAQ

适合写成 FAQ 的内容：

- 有明确现象和解决步骤的问题。
- 高频报错。
- 环境配置问题。
- 部署或协作中的常见坑。

## 文件命名

文件名使用简短英文，便于 URL 分享和长期维护。

示例：

```txt
docs/documents/frontend.md
docs/faq/deploy.md
```

## 页面结构

每个页面建议包含：

- 清晰的标题。
- 简短的描述。
- 可扫描的小标题。
- 必要的代码块或表格。
- 相关页面链接。

如果页面内容影响线上行为，请注明适用版本或更新时间。
