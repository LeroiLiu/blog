ThinkPHP 3.2 多见于历史项目。维护重点不是追新，而是先保证项目能稳定运行、日志可查、备份完整、权限清楚。

## 适合场景

- 已上线多年、仍在运行的旧业务系统。
- 只需要修复少量 bug 或做小功能。
- 暂时无法升级 PHP 或框架的大型老项目。

## 常见目录

```txt
Application/
Public/
ThinkPHP/
index.php
```

常见模块会放在 `Application` 下，例如：

```txt
Application/Home/
Application/Admin/
```

## 维护重点

| 项目 | 建议 |
| --- | --- |
| PHP 版本 | 先确认线上 PHP 版本，不要随意升级运行环境 |
| 入口文件 | 检查 `index.php`、模块绑定和调试配置 |
| 配置文件 | 注意数据库、缓存、URL 模式和日志配置 |
| 缓存目录 | 确认运行缓存可写，异常时可以清理缓存 |
| 安全 | 后台入口、上传目录、调试模式都要重点检查 |

## 常见问题

### 开启调试后页面暴露错误

生产环境不要开启调试模式。调试信息可能包含数据库账号、文件路径和代码结构。

### 修改代码后不生效

可能是运行缓存没有清理。先确认项目是否开启缓存，再清理对应运行目录。

### 上传目录无法写入

检查上传目录权限，以及 PHP-FPM 或 Web 服务运行用户。

## 升级建议

ThinkPHP 3.2 到 5.x、6.x、8.x 都不是简单替换依赖，通常涉及目录结构、命名空间、路由、模型和配置方式变化。建议按模块逐步重构，而不是直接整体升级。
